Web 개념 친절한 설명 정리

자료 성격: 강의용 위키 정리

이 문서는 웹의 기본 개념을 IYO Wiki / WackoWiki 문법에 맞춰 정리한 자료입니다.
먼저 WWW, World Wide Web이 무엇인지 살펴본 뒤, 웹 페이지의 구조를 만드는 HTML을 설명합니다.
그다음 웹 페이지의 표현과 동작을 담당하는 CSS, JavaScript를 이어서 설명합니다.
이후 J. R. Carpenter의 Handmade Web, Olia Lialina의 Vernacular Web, Elliott Cost와 Laurel Schwulst의 HTML Energy를 통해 HTML을 단순한 기술이 아니라 글쓰기와 핸드메이드 미학의 도구로 이해합니다.
마지막으로 웹사이트를 실제로 공개하고 운영하기 위해 필요한 호스팅, 클라우드, 데이터베이스, GitHub, 라이브러리, 패키지, 로컬 서버 개념을 정리합니다.

1. WWW, World Wide Web

1.1. WWW는 무엇인가

WWW는 World Wide Web의 줄임말입니다.
한국어로는 보통 월드 와이드 웹, 또는 간단히 웹이라고 부릅니다.

웹은 인터넷 위에서 작동하는 정보 연결 시스템입니다.
웹 브라우저, 웹 서버, URL, HTTP 또는 HTTPS, HTML 문서, 링크가 서로 연결되면서 우리가 보는 웹사이트와 웹앱이 만들어집니다.

여기서 중요한 점은 인터넷과 웹이 완전히 같은 말은 아니라는 것입니다.

  • 인터넷: 전 세계 컴퓨터와 서버가 서로 연결된 거대한 네트워크
  • 웹: 그 인터넷 위에서 문서와 자료를 찾아보고 연결하는 방식

도로망 비유로 말하면 인터넷은 도로망이고, 웹은 그 도로 위에서 사람들이 찾아가는 가게, 표지판, 주소, 안내 지도에 가깝습니다.
이메일, 파일 전송, 온라인 게임, 메신저도 인터넷을 사용할 수 있지만, 모두가 웹인 것은 아닙니다.
웹은 브라우저로 주소를 열고, 링크를 클릭하고, 페이지를 읽는 방식의 정보 시스템입니다.

1.2. WWW는 왜 만들어졌는가

World Wide Web은 1989년 CERN에서 일하던 팀 버너스리가 제안한 정보 공유 시스템에서 시작했습니다.
CERN은 여러 나라의 과학자들이 함께 연구하는 곳이었기 때문에, 서로 다른 컴퓨터와 기관에 흩어진 문서와 정보를 연결해서 쉽게 찾아볼 방법이 필요했습니다.

초기의 웹은 오늘날처럼 쇼핑몰, SNS, 영상 플랫폼, 광고 시스템으로 가득한 공간이 아니었습니다.
핵심 목표는 흩어진 문서를 서로 연결하고, 누구나 브라우저로 읽고 이동할 수 있게 만드는 것이었습니다.

웹이 특별했던 이유는 하이퍼텍스트라는 개념 때문입니다.
하이퍼텍스트는 문서 안의 특정 단어나 문장을 다른 문서와 연결하는 방식입니다.
우리가 지금 웹에서 누르는 링크가 바로 그 핵심입니다.

책은 보통 앞에서 뒤로 읽습니다.
하지만 웹은 링크를 따라 옆으로, 위로, 다른 사이트로 계속 이동할 수 있습니다.
이 연결 방식이 웹을 거대한 문서의 그물처럼 만들었습니다.

1.3. 첫 번째 웹사이트와 웹 서버

1990년 말, 팀 버너스리는 첫 웹 브라우저와 첫 웹 서버를 CERN에서 작동시켰습니다.
세계 최초의 웹사이트와 웹 서버 주소는 info.cern.ch였습니다.

그 첫 웹페이지는 웹 프로젝트 자체를 설명하는 문서였습니다.
웹이 무엇인지, 하이퍼텍스트가 무엇인지, 웹 서버를 어떻게 만드는지, 다른 웹 서버로 어떻게 연결되는지 같은 정보를 담고 있었습니다.

이 점이 재미있습니다.
첫 웹사이트는 화려한 홍보 페이지가 아니라, 웹을 설명하고 웹을 만들 수 있게 돕는 문서였습니다.
웹은 처음부터 정보를 공유하고, 다른 사람이 그 구조를 이어받아 확장할 수 있게 하는 쪽에 가까웠습니다.

1993년 CERN은 WorldWideWeb의 소스 코드를 로열티 없이 공개했습니다.
이 공개성은 웹이 전 세계로 퍼지는 데 매우 중요했습니다.
누구나 웹 기술을 가져다 쓰고, 브라우저를 만들고, 서버를 세우고, 페이지를 만들 수 있었기 때문입니다.

1.4. 웹이 작동하는 기본 흐름

우리가 브라우저에 주소를 입력하면 여러 일이 차례로 일어납니다.

  • 사용자가 브라우저에 주소를 입력합니다.
  • 브라우저가 도메인 이름을 보고 실제 서버의 주소를 찾습니다.

  * 이때 DNS가 사용됩니다.
  * DNS는 Domain Name System의 줄임말입니다.
  * 사람이 읽기 쉬운 주소를 컴퓨터가 찾을 수 있는 IP 주소로 바꿔주는 주소록 같은 역할을 합니다.

  • 브라우저는 해당 서버에 HTTP 또는 HTTPS 요청을 보냅니다.

  * HTTP는 Hypertext Transfer Protocol의 줄임말입니다.
  * 브라우저와 서버가 서로 대화하기 위한 약속입니다.
  * HTTPS는 그 통신을 암호화해서 더 안전하게 만든 방식입니다.

  • 서버는 요청받은 HTML, CSS, JavaScript, 이미지, 폰트, 영상 같은 파일을 브라우저로 보냅니다.
  • 브라우저는 이 파일들을 해석해서 우리가 보는 화면으로 조립합니다.

정리하면 흐름은 이렇습니다.

#|
*| 순서 | 설명 |*
|| 1 | 사용자가 주소를 입력합니다. ||
|| 2 | 브라우저가 DNS를 통해 서버 위치를 찾습니다. ||
|| 3 | 브라우저가 서버에 요청을 보냅니다. ||
|| 4 | 서버가 웹사이트 파일을 돌려줍니다. ||
|| 5 | 브라우저가 HTML, CSS, JavaScript 등을 해석해 화면을 만듭니다. ||
|#

1.5. www는 꼭 붙어야 하는가

많은 웹사이트 주소는 www로 시작합니다.
예를 들어 www.example.com 같은 형태입니다.

여기서 www는 World Wide Web을 뜻하지만, 기술적으로는 도메인 앞에 붙는 하위 도메인입니다.
즉 www.example.com과 example.com은 설정에 따라 같은 사이트를 보여줄 수도 있고, 서로 다른 사이트를 보여줄 수도 있습니다.

요즘은 www를 생략하는 사이트도 많습니다.
중요한 것은 www라는 글자 자체가 아니라, 도메인과 서버가 어떤 식으로 연결되어 있는가입니다.

수업에서는 이렇게 설명하면 좋습니다.

<[WWW는 웹이라는 정보 시스템 전체를 가리키는 말입니다.
주소 앞의 www는 그 흔적이 남은 하위 도메인 이름입니다.
www가 붙어 있든 없든, 브라우저가 웹 서버에 접속해서 페이지를 받아오면 우리는 웹을 사용하고 있는 것입니다.]>

2. HTML

2.1. HTML은 웹의 구조를 만드는 언어

HTML은 HyperText Markup Language의 줄임말입니다.
웹 페이지의 내용과 구조를 만드는 마크업 언어입니다.

HTML 구조로 보면, HTML은 웹 페이지의 뼈대입니다.
제목, 문단, 링크, 이미지, 목록, 버튼, 입력 폼, 표, 동영상 같은 요소가 페이지 안에서 어떤 의미를 갖는지 표시합니다.

HTML은 프로그래밍 언어라기보다 마크업 언어입니다.
마크업은 텍스트와 콘텐츠에 의미를 붙이는 방식입니다.
예를 들어 어떤 문장은 제목이고, 어떤 문장은 본문이고, 어떤 단어는 링크이고, 어떤 이미지는 설명이 필요하다는 식으로 표시합니다.

브라우저는 HTML을 읽고 문서의 구조를 이해합니다.
검색엔진도 HTML 구조를 보고 페이지가 무엇에 관한 것인지 파악합니다.
스크린리더 같은 보조 기술도 HTML의 의미 구조를 바탕으로 사용자에게 내용을 전달합니다.

그래서 HTML은 단순히 화면에 글자를 띄우는 기술이 아닙니다.
웹 문서의 의미를 정리하는 기술입니다.

2.2. HTML의 핵심은 링크와 문서성

HTML에서 가장 중요한 요소 중 하나는 링크입니다.
링크는 한 문서에서 다른 문서로 이동하는 연결입니다.

웹이 책이나 PDF와 다른 점은 문서가 고정된 한 덩어리로 끝나지 않는다는 것입니다.
HTML 문서는 다른 문서와 연결될 수 있고, 사용자는 그 연결을 따라 계속 이동할 수 있습니다.

이 때문에 HTML은 글쓰기와도 깊이 연결됩니다.
HTML로 글을 쓴다는 것은 단순히 문장을 입력하는 것이 아니라, 문장의 구조와 연결 관계를 함께 만드는 일입니다.

HTML 글짓기는 문장뿐 아니라 이동 경로를 설계하는 일입니다.

HTML로 글을 쓸 때 우리는 다음을 결정합니다.

  • 어떤 문장을 제목으로 둘 것인가.
  • 어떤 문장을 본문으로 둘 것인가.
  • 어떤 단어를 링크로 만들 것인가.
  • 어떤 이미지를 넣고 어떤 설명을 붙일 것인가.
  • 어떤 목록을 만들고 어떤 순서로 보여줄 것인가.
  • 어떤 페이지와 어떤 페이지를 연결할 것인가.

이런 선택은 모두 글쓰기의 일부입니다.
HTML은 글을 화면에 올리는 포장지가 아니라, 글의 구조와 리듬과 이동 경로를 만드는 도구입니다.

2.3. HTML은 핸드메이드 웹의 출발점

HTML은 비교적 작고 접근하기 쉬운 언어입니다.
물론 현대 웹 개발은 매우 복잡해졌지만, HTML 자체만 놓고 보면 누구나 텍스트 편집기로 시작할 수 있습니다.

파일 하나를 만들고, 제목과 문단과 링크를 적고, 브라우저로 열면 작은 웹페이지가 됩니다.
이 단순함은 매우 중요합니다.

웹이 거대한 플랫폼과 자동화 도구의 공간이 된 지금도, HTML은 여전히 개인이 직접 페이지를 만들 수 있는 작은 입구입니다.
HTML을 손으로 쓴다는 것은 웹을 소비만 하는 것이 아니라, 웹에 직접 작은 방을 만드는 행위에 가깝습니다.

이 관점은 뒤에서 설명할 J. R. Carpenter의 Handmade Web, Elliott Cost와 Laurel Schwulst의 HTML Energy와도 연결됩니다.

3. CSS

3.1. CSS는 웹의 시각적 표현을 만드는 언어

CSS는 Cascading Style Sheets의 줄임말입니다.
HTML 문서가 화면에 어떻게 보일지 정하는 스타일 언어입니다.

HTML이 구조라면 CSS는 표현입니다.
색, 글꼴, 크기, 여백, 줄 간격, 배치, 배경, 테두리, 반응형 레이아웃, 일부 애니메이션을 CSS로 지정합니다.

같은 HTML 문서라도 CSS를 어떻게 쓰느냐에 따라 전혀 다른 분위기가 됩니다.
단정한 논문처럼 보일 수도 있고, 잡지처럼 보일 수도 있고, 개인 홈페이지처럼 보일 수도 있고, 앱 화면처럼 보일 수도 있습니다.

CSS는 단순히 꾸미는 도구가 아닙니다.
정보를 더 잘 읽히게 하고, 중요한 것을 눈에 띄게 하고, 사용자가 길을 잃지 않게 만드는 시각적 구조화 도구입니다.

3.2. CSS가 HTML과 분리되는 이유

HTML은 내용과 의미를 담당합니다.
CSS는 그 내용이 어떻게 보일지 담당합니다.

이 둘을 분리하면 여러 장점이 생깁니다.

  • 문서 구조가 깨끗해집니다.
  • 디자인을 한곳에서 관리하기 쉬워집니다.
  • 같은 HTML에 다른 CSS를 적용해 다른 느낌을 만들 수 있습니다.
  • 여러 페이지에서 같은 스타일을 재사용할 수 있습니다.
  • 접근성과 유지보수에 유리합니다.

예를 들어 HTML에는 이것은 제목이다라는 의미를 적고, CSS에는 그 제목은 크게, 진한 색으로, 위아래 여백을 두고 보여준다라고 적는 식입니다.

이 분리는 웹의 중요한 철학 중 하나입니다.
내용과 표현을 구분하면, 웹 페이지는 더 오래 유지되고 더 유연하게 바뀔 수 있습니다.

3.3. CSS는 분위기와 리듬을 만든다

웹 페이지를 읽을 때 우리는 단어만 읽지 않습니다.
여백, 줄 간격, 글자 크기, 색의 대비, 이미지 위치, 스크롤 리듬까지 함께 느낍니다.

CSS 리듬은 이 감각을 만듭니다.

  • 여백이 좁으면 답답하게 느껴질 수 있습니다.
  • 줄 간격이 너무 좁으면 긴 글을 읽기 어렵습니다.
  • 색 대비가 낮으면 시력이 좋지 않은 사용자는 내용을 읽기 힘듭니다.
  • 버튼의 크기와 위치가 애매하면 사용자가 어디를 눌러야 할지 헷갈립니다.

좋은 CSS는 단순히 예쁘게 만드는 것이 아닙니다.
내용을 더 정확하고 편안하게 전달하도록 돕습니다.

4. JavaScript

4.1. JavaScript는 웹의 동작을 만드는 언어

JavaScript는 웹 페이지에 동작과 상호작용을 추가하는 프로그래밍 언어입니다.
줄여서 JS라고도 부릅니다.

사용자가 "java"라고 말하는 경우가 있지만, 웹의 HTML, CSS 다음에 보통 배우는 것은 Java가 아니라 JavaScript입니다.
Java와 JavaScript는 이름이 비슷하지만 서로 다른 언어입니다.
웹 초급 흐름에서는 HTML, CSS, JavaScript 순서로 이해하면 됩니다.

HTML이 구조를 만들고, CSS가 표현을 만들고, JavaScript가 동작을 만듭니다.

JavaScript는 다음과 같은 일을 합니다.

  • 버튼을 누르면 메뉴가 열리게 합니다.
  • 입력한 이메일 형식이 맞는지 확인합니다.
  • 서버에서 데이터를 가져와 화면을 바꿉니다.
  • 이미지 슬라이더를 움직입니다.
  • 채팅 메시지를 추가합니다.
  • 장바구니 수량을 바꿉니다.
  • 지도, 그래프, 게임, 인터랙티브 작품을 만듭니다.

4.2. 정적인 페이지와 동적인 페이지

HTML과 CSS만으로도 웹 페이지를 만들 수 있습니다.
이런 페이지는 주로 정적인 페이지입니다.
사용자가 읽고 이동할 수는 있지만, 화면이 복잡하게 반응하지는 않습니다.

JavaScript가 들어가면 페이지는 더 동적으로 변합니다.
사용자의 클릭, 입력, 스크롤, 시간 변화, 서버 데이터에 따라 화면이 바뀔 수 있습니다.

예를 들어 날씨 앱은 서버에서 최신 날씨 데이터를 가져와 화면을 바꿉니다.
온라인 쇼핑몰은 사용자가 옵션을 고르면 가격과 재고 표시가 바뀝니다.
LMS는 수강 상태, 댓글, 퀴즈 결과를 실시간으로 보여줄 수 있습니다.

이런 변화에는 JavaScript가 자주 사용됩니다.

4.3. JavaScript는 브라우저 안에서도, 서버에서도 쓰인다

처음에는 JavaScript를 브라우저 안에서 실행되는 언어로 배우는 경우가 많습니다.
브라우저 안에서 HTML과 CSS를 바꾸고, 버튼 클릭에 반응하고, 사용자 인터페이스를 움직입니다.

하지만 현대 JavaScript는 서버 쪽에서도 쓰입니다.
Node.js 같은 환경을 사용하면 JavaScript로 서버 프로그램, 개발 도구, 자동화 스크립트를 만들 수 있습니다.

그래서 JavaScript는 웹 프론트엔드의 언어이면서, 동시에 웹 개발 전체에서 넓게 쓰이는 언어가 되었습니다.

5. HTML과 글짓기, Handmade Web 미학

5.1. 왜 HTML을 글짓기로 볼 수 있는가

HTML은 웹 페이지의 구조를 만드는 기술이지만, 동시에 글쓰기의 방식이기도 합니다.

종이에 글을 쓸 때 우리는 문단을 나누고, 제목을 붙이고, 중요한 문장을 강조하고, 참고 자료를 연결합니다.
HTML에서도 비슷한 일을 합니다.
다만 HTML에서는 그 구조가 브라우저와 검색엔진과 다른 사람의 코드 읽기까지 이어집니다.

HTML로 글을 쓴다는 것은 다음을 함께 결정하는 일입니다.

  • 무엇을 제목으로 삼을 것인가.
  • 본문을 어떤 문단으로 나눌 것인가.
  • 어떤 단어에 링크를 걸 것인가.
  • 이미지에 어떤 설명을 붙일 것인가.
  • 목록과 표를 어떻게 구성할 것인가.
  • 글을 읽는 사람이 어디로 이동하게 할 것인가.

그래서 HTML은 단순한 기술 문법이 아닙니다.
웹에서 생각을 배치하고, 독자의 이동 경로를 만들고, 글과 이미지와 링크를 엮는 글짓기 도구입니다.

5.2. J. R. Carpenter와 A Handmade Web

J. R. Carpenter는 디지털 문학, 웹 기반 글쓰기, 넷아트와 관련된 작가입니다.
그의 글 A Handmade Web은 손으로 만든 웹, 직접 코딩한 웹, 개인이 유지하는 웹의 의미를 설명하는 중요한 글로 자주 언급됩니다.

이 글에서 말하는 handmade web은 단순히 오래된 웹 디자인을 흉내 내자는 이야기가 아닙니다.
핵심은 웹페이지가 개인의 손으로 만들어지고, 개인이 유지하며, 임시적이고 실험적이고 하나뿐인 결과물이 될 수 있다는 점입니다.

Carpenter가 주목하는 handmade web의 특징은 다음과 같이 정리할 수 있습니다.

  • 손으로 직접 코딩한 페이지입니다.
  • 기업이나 플랫폼보다 개인의 제작과 유지가 중요합니다.
  • 완성된 상품이라기보다 임시적이고 변하는 작업일 수 있습니다.
  • 읽기, 쓰기, 디자인, 소유권, 개인정보, 정체성에 대한 기존 관습을 흔들 수 있습니다.
  • 느린 제작과 느린 읽기를 가능하게 합니다.
  • 소스 코드를 보고 배우고 변형하는 문화와 연결됩니다.

여기서 중요한 단어는 느림입니다.
핸드메이드 웹은 빠르게 소비되는 피드와 다릅니다.
한 사람이 직접 만들고, 고치고, 링크를 붙이고, 어색한 부분까지 남기는 웹입니다.
그래서 완벽하게 매끈한 제품보다 사람의 손이 보이는 문서에 가깝습니다.

5.3. 손코딩과 느린 읽기

현대 웹은 매우 빠릅니다.
우리는 SNS 피드를 넘기고, 추천 알고리즘이 보여주는 글과 영상을 계속 소비합니다.
이 환경에서는 페이지 하나를 오래 읽거나, 누가 어떻게 만들었는지 생각하기 어렵습니다.

반대로 핸드메이드 웹은 느립니다.
만드는 사람은 HTML을 직접 쓰고, 작은 파일을 정리하고, 링크를 손으로 연결합니다.
읽는 사람은 페이지의 구조와 흐름, 링크의 배치, 이미지와 텍스트의 관계를 천천히 따라갑니다.

이 느림은 단점만은 아닙니다.
오히려 웹을 다시 글쓰기와 만들기의 공간으로 느끼게 합니다.
페이지를 보는 사람이 소비자만이 아니라, 자신도 만들 수 있는 사람이라는 감각을 줍니다.

5.4. Olia Lialina와 버내큘러 웹

J. R. Carpenter의 Handmade Web 논의는 Olia Lialina의 Vernacular Web 논의와도 연결됩니다.
Vernacular Web은 전문 디자이너나 대기업 플랫폼이 만들기 전, 개인과 아마추어들이 자기 방식으로 만들던 초기 웹의 표현 문화를 가리킵니다.

초기 개인 홈페이지에는 반짝이는 GIF, 공사중 표시, 강한 배경 이미지, 방문자 카운터, 링크 모음, 개인적인 문장들이 많았습니다.
오늘날의 기준으로 보면 투박하거나 어수선해 보일 수 있지만, 그 안에는 개인이 자기 공간을 만들고 있다는 강한 감각이 있었습니다.

버내큘러 웹을 이해할 때 중요한 것은 촌스럽다가 아니라 자기 언어가 있다입니다.
전문가가 만든 매끈한 디자인이 아니어도, 개인의 취향과 시간과 손길이 남아 있는 웹은 하나의 문화입니다.

5.5. Elliott Cost와 HTML Energy

Elliott Cost는 컴퓨터 아티스트, 디자이너, 프로그래머로 소개됩니다.
그는 File Life, Special Fish, Gossip's Web 같은 시적이고 실험적인 웹 프로젝트를 운영해왔고, Laurel Schwulst와 함께 HTML Energy라는 움직임과 팟캐스트를 만들었습니다.

HTML Energy는 HTML의 단순함, 접근성, 직접 쓰는 즐거움을 강조합니다.
현대 웹 제작은 프레임워크, 빌드 도구, 배포 시스템, 복잡한 앱 구조로 점점 어려워졌지만, HTML에는 여전히 누구나 웹에 무언가를 출판할 수 있게 하는 에너지가 있다는 관점입니다.

HTML Energy 사이트 자체도 순수한 HTML 감각을 전면에 드러냅니다.
화려한 프레임워크보다 소스 보기, 직접 쓰기, 작은 페이지 만들기의 즐거움을 보여줍니다.

Elliott Cost의 작업에서 웹사이트는 단순한 포트폴리오가 아닙니다.
웹사이트는 카메라, 노트, 지도, 아카이브, 커뮤니티, 산책로, 편지 같은 역할을 합니다.
Gossip's Web은 작은 프로젝트 공간과 아파트 갤러리들을 엮는 웹적 목록이었고, File Life는 파일과 USB, 이동, 삭제, 기억을 다루는 웹 기반 프로젝트였습니다.

이런 작업들은 웹을 정보를 올려두는 곳이 아니라 생활과 관계와 기억을 담는 그릇으로 보여줍니다.

5.6. HTML 헤비 유저라는 감각

여기서 말하는 HTML 헤비 유저는 단순히 HTML을 많이 아는 개발자를 뜻하지 않습니다.
HTML을 자기 표현의 주된 도구로 삼고, 웹사이트를 직접 만들고, 링크와 문서와 파일을 자기 방식으로 엮는 사람들을 가리킬 수 있습니다.

이들은 웹을 완성된 플랫폼 안에서만 쓰지 않습니다.
자신의 도메인, 자신의 파일, 자신의 HTML 문서, 자신의 링크 구조를 통해 웹 위에 작은 세계를 만듭니다.

HTML 헤비 유저의 태도는 다음과 같습니다.

  • 웹페이지를 직접 쓸 수 있는 종이처럼 여깁니다.
  • 소스 코드를 숨겨진 내부가 아니라 읽을 수 있는 재료로 봅니다.
  • 디자인의 매끈함보다 페이지의 성격과 목소리를 중요하게 생각합니다.
  • 작고 느린 웹사이트도 충분히 가치 있다고 봅니다.
  • 플랫폼 계정이 아니라 자기 주소와 자기 파일을 중요하게 생각합니다.
  • 웹을 소비 공간이 아니라 출판과 연결의 공간으로 봅니다.

5.7. 핸드메이드 웹 미학 정리

핸드메이드 웹 미학은 단순히 복고풍 웹 디자인이 아닙니다.
그보다 더 깊은 태도입니다.

#|
*| 관점 | 설명 |*
|| 손의 흔적 | 완전히 자동화되고 매끈한 화면보다, 만든 사람이 어떤 선택을 했는지 보이는 페이지를 긍정합니다. ||
|| 작은 규모 | 작은 메모, 개인 노트, 링크 모음, 실험적 글쓰기, 수업 자료도 웹의 중요한 형태입니다. ||
|| 읽기와 쓰기 | 웹을 잘 읽는 사람은 링크와 구조를 보고, 웹을 잘 쓰는 사람은 HTML과 CSS를 통해 생각을 배치합니다. ||
|| 소유와 독립성 | 플랫폼 게시물은 편리하지만 플랫폼 규칙에 묶입니다. 자기 HTML 파일과 자기 도메인은 더 직접적인 소유감을 줍니다. ||
|| 불완전함 | 공사중 표시, 직접 만든 버튼, 어색한 배경, 링크 모음은 누군가가 배우며 만들었다는 증거입니다. ||
|| 공방으로서의 웹 | HTML 파일을 열고, 문장을 쓰고, 링크를 걸고, 브라우저에서 확인하는 일은 작은 공예에 가깝습니다. ||
|#

이 감각은 AI 시대에도 중요합니다.
AI가 코드를 만들어줄 수 있어도, 어떤 페이지를 왜 만들고 어떤 목소리로 남길지는 여전히 사람의 선택이기 때문입니다.

6. 호스팅, Hosting

6.1. 호스팅은 웹사이트가 머무는 자리

호스팅은 웹사이트 파일을 인터넷에서 접근 가능한 서버에 올려두는 일입니다.

내 컴퓨터에 HTML 파일이 있으면 나만 열어볼 수 있습니다.
다른 사람이 브라우저로 접속하려면, 그 파일이 항상 켜져 있고 인터넷에 연결된 서버 어딘가에 있어야 합니다.
이 서버 공간을 빌리거나 제공받아 웹사이트를 공개하는 것이 호스팅입니다.

비유하면 다음과 같습니다.

  • 도메인: 가게 주소
  • 호스팅: 가게가 실제로 들어가 있는 건물
  • HTML, CSS, JavaScript, 이미지 파일: 가게 안에 놓인 물건들
  • 브라우저: 손님
  • 서버: 손님에게 물건을 보여주는 직원

6.2. 정적 사이트 호스팅

정적 사이트는 HTML, CSS, JavaScript, 이미지 파일만으로 구성된 사이트입니다.
서버에서 복잡한 계산을 하지 않고, 이미 준비된 파일을 브라우저에 보내줍니다.

개인 홈페이지, 포트폴리오, 간단한 수업 자료, 문서 사이트, 랜딩 페이지는 정적 사이트로 충분한 경우가 많습니다.

GitHub Pages는 대표적인 정적 사이트 호스팅 예시입니다.
GitHub 저장소에 있는 HTML, CSS, JavaScript 파일을 웹사이트로 공개할 수 있습니다.

정적 사이트의 장점은 단순함입니다.
구조가 가볍고, 빠르고, 보안 관리가 상대적으로 쉽습니다.
데이터베이스나 서버 프로그램이 꼭 필요하지 않은 경우에는 좋은 선택입니다.

6.3. 동적 사이트 호스팅

동적 사이트는 사용자의 요청이나 데이터베이스 내용에 따라 페이지가 달라지는 사이트입니다.

예를 들어 로그인한 사용자마다 다른 화면을 보여주는 LMS, 장바구니가 있는 쇼핑몰, 댓글이 실시간으로 바뀌는 커뮤니티, 예약 시스템, 관리자 페이지는 동적 사이트입니다.

동적 사이트에는 보통 서버 프로그램과 데이터베이스가 필요합니다.
서버는 사용자의 요청을 처리하고, 데이터베이스에서 필요한 정보를 가져오고, 결과를 브라우저에 보냅니다.

정적 사이트가 준비된 파일을 보여주는 방식이라면, 동적 사이트는 상황에 맞게 내용을 만들어 보내는 방식에 가깝습니다.

6.4. 도메인과 호스팅의 관계

도메인은 사람이 기억하기 쉬운 웹 주소입니다.
예를 들어 example.com 같은 이름입니다.

호스팅은 파일과 서버가 있는 실제 위치입니다.
도메인은 그 서버 위치를 가리키도록 설정됩니다.

도메인과 호스팅을 같은 회사에서 살 수도 있고, 서로 다른 회사에서 관리할 수도 있습니다.
서로 다른 회사에서 관리한다면 DNS 설정을 통해 도메인이 올바른 서버를 가리키게 해야 합니다.

초보자에게는 이 관계가 헷갈릴 수 있습니다.
쉽게 말해 도메인과 호스팅의 관계를 비유로 보면 도메인은 간판, 호스팅은 건물, DNS는 간판이 어느 건물을 가리키는지 정하는 주소 안내 시스템입니다.

7. 클라우드, Cloud

7.1. 클라우드는 인터넷으로 빌려 쓰는 컴퓨팅 자원

클라우드는 서버, 저장소, 네트워크, 데이터베이스, 애플리케이션 같은 컴퓨팅 자원을 인터넷을 통해 필요할 때 빌려 쓰는 방식입니다.

예전에는 회사나 개인이 직접 서버 장비를 사고, 설치하고, 전기를 연결하고, 네트워크를 관리해야 했습니다.
클라우드는 이런 자원을 직접 소유하지 않고도 인터넷으로 사용할 수 있게 합니다.

비유하면 클라우드는 컴퓨터 자원의 수도꼭지와 비슷합니다.
물을 직접 만들지 않아도 수도를 틀어 쓰듯이, 서버를 직접 사지 않아도 필요한 만큼 컴퓨팅 자원을 켜고 끄고 확장할 수 있습니다.

7.2. 클라우드와 호스팅의 차이

호스팅은 웹사이트를 인터넷에 올려두는 행위나 서비스를 넓게 말합니다.
클라우드는 그 호스팅을 포함할 수 있는 더 넓은 컴퓨팅 자원 제공 방식입니다.

작은 개인 홈페이지는 정적 호스팅만으로 충분할 수 있습니다.
하지만 사용자가 많아지고, 로그인, 데이터베이스, 파일 업로드, 이미지 처리, AI 기능, 백업, 보안, 확장성이 필요해지면 클라우드 서비스를 쓰는 경우가 많습니다.

즉 호스팅은 웹사이트를 어디에 올릴 것인가에 가까운 말이고, 클라우드는 서버, 저장소, 데이터베이스, 네트워크 같은 자원을 인터넷으로 유연하게 빌려 쓰는 방식에 가깝습니다.

7.3. IaaS, PaaS, SaaS

클라우드는 서비스 수준에 따라 여러 방식으로 나눌 수 있습니다.

#|
*| 구분 | 뜻 | 쉬운 비유 |*
|| IaaS | Infrastructure as a Service. 서버, 저장소, 네트워크 같은 기초 인프라를 빌려 쓰는 방식입니다. 자유도가 높지만 운영 책임도 큽니다. | 빈 작업실을 빌리는 것 ||
|| PaaS | Platform as a Service. 앱을 올리면 서버 관리의 많은 부분을 플랫폼이 대신 처리해주는 방식입니다. | 기본 장비가 갖춰진 작업실을 빌리는 것 ||
|| SaaS | Software as a Service. 이미 완성된 소프트웨어를 인터넷으로 사용하는 방식입니다. Gmail, Notion, Google Docs 같은 서비스가 예입니다. | 완성된 서비스를 바로 사용하는 것 ||
|#

7.4. 클라우드가 중요한 이유

클라우드는 웹 프로젝트를 빠르게 시작하고, 필요할 때 확장할 수 있게 해줍니다.

사용자가 적을 때는 작은 서버로 시작하고, 사용자가 많아지면 서버나 데이터베이스 자원을 늘릴 수 있습니다.
파일 저장소, 이미지 처리, 데이터베이스, 인증, 로그, 모니터링 같은 기능도 서비스로 붙일 수 있습니다.

하지만 클라우드는 마법이 아닙니다.
설정을 잘못하면 비용이 커질 수 있고, 보안 설정을 잘못하면 데이터가 노출될 수 있습니다.
그래서 클라우드를 쓸 때는 비용, 권한, 백업, 로그, 지역, 개인정보 보호를 함께 고려해야 합니다.

8. 데이터베이스, Database

8.1. 데이터베이스는 데이터를 정리해 보관하는 시스템

데이터베이스는 데이터를 체계적으로 저장하고, 관리하고, 안전하게 꺼내 쓸 수 있게 하는 시스템입니다.

웹사이트가 단순한 정적 페이지라면 데이터베이스가 필요 없을 수도 있습니다.
하지만 사용자가 로그인하고, 글을 쓰고, 댓글을 남기고, 결제를 하고, 수강 기록이 저장되고, 관리자 화면에서 데이터를 조회해야 한다면 데이터베이스가 필요합니다.

데이터베이스는 웹앱의 기억에 가깝습니다.
HTML이 화면의 구조라면, 데이터베이스는 서비스가 기억해야 하는 정보를 보관합니다.

8.2. 데이터베이스에 들어가는 것들

웹 서비스의 데이터베이스에는 다음과 같은 정보가 들어갈 수 있습니다.

  • 회원 정보
  • 로그인 계정
  • 게시글
  • 댓글
  • 수강 기록
  • 주문 내역
  • 상품 정보
  • 파일 메타데이터
  • 결제 상태
  • 권한 정보
  • 검색용 데이터
  • AI 검색이나 추천을 위한 벡터 데이터

중요한 점은 데이터베이스가 단순한 파일 보관함이 아니라는 것입니다.
데이터를 검색하고, 정렬하고, 연결하고, 수정하고, 삭제하고, 권한을 관리할 수 있어야 합니다.

8.3. 관계형 데이터베이스와 SQL

관계형 데이터베이스는 데이터를 표처럼 저장합니다.
행과 열로 구성된 테이블을 만들고, 테이블 사이의 관계를 정의합니다.

예를 들어 회원 테이블, 강의 테이블, 수강 신청 테이블을 따로 만들 수 있습니다.
한 명의 회원이 여러 강의를 수강할 수 있고, 하나의 강의에는 여러 회원이 연결될 수 있습니다.
이 관계를 잘 설계하는 것이 중요합니다.

SQL은 Structured Query Language의 줄임말입니다.
관계형 데이터베이스에서 데이터를 조회하고 수정하기 위해 사용하는 언어입니다.

예를 들어 다음과 같은 요청을 SQL로 표현할 수 있습니다.

  • 이 회원이 수강 중인 강의를 보여줘.
  • 결제가 완료된 주문만 찾아줘.
  • 이번 달 가입자 수를 세어줘.

8.4. NoSQL과 다양한 데이터베이스

모든 데이터가 표 형태에 잘 맞는 것은 아닙니다.
문서, 그래프, 키-값, 로그, 대규모 이벤트 데이터처럼 다른 구조가 더 적합한 경우도 있습니다.

이런 경우 NoSQL 데이터베이스를 사용할 수 있습니다.
NoSQL은 하나의 제품 이름이 아니라, 전통적인 관계형 테이블 방식과 다른 여러 데이터베이스 방식을 넓게 부르는 말입니다.

  • 문서형 데이터베이스: JSON 같은 문서 구조를 저장하기 좋습니다.
  • 그래프 데이터베이스: 사람과 사람, 장소와 장소, 개념과 개념 사이의 관계를 표현하기 좋습니다.
  • 키-값 저장소: 캐시나 세션처럼 빠르게 읽고 쓰는 데이터에 자주 쓰입니다.

8.5. AI 시대의 데이터베이스

AI 시대에는 데이터베이스의 역할이 더 중요해집니다.
AI가 좋은 답을 하려면 좋은 데이터에 접근해야 하기 때문입니다.

예를 들어 회사 문서를 AI가 검색해서 답하게 하려면 문서가 잘 저장되어 있어야 합니다.
수강생의 학습 기록을 분석하려면 기록이 안정적으로 쌓여야 합니다.
이미지나 문서 검색을 하려면 일반 텍스트 검색뿐 아니라 벡터 데이터베이스가 필요할 수도 있습니다.

데이터베이스는 AI의 기억 창고이자, 서비스 운영의 근거입니다.
하지만 개인정보와 민감한 데이터가 들어갈 수 있으므로 권한 관리, 암호화, 백업, 삭제 정책을 신중히 다뤄야 합니다.

9. GitHub

9.1. GitHub는 코드 저장과 협업 플랫폼

GitHub는 Git 저장소를 기반으로 코드를 저장하고 협업하는 클라우드 플랫폼입니다.

Git은 코드의 변경 이력을 관리하는 도구입니다.
누가 언제 어떤 파일을 어떻게 바꿨는지 기록하고, 필요하면 이전 상태와 비교할 수 있게 해줍니다.

GitHub는 이 Git 저장소를 온라인에서 관리하고 협업할 수 있게 해줍니다.
개발자들이 같은 프로젝트에서 함께 작업하고, 변경 사항을 리뷰하고, 이슈를 관리하고, 자동 테스트나 배포를 연결할 수 있습니다.

9.2. GitHub Pages

GitHub Pages는 GitHub 저장소의 HTML, CSS, JavaScript 파일을 웹사이트로 공개할 수 있게 해주는 정적 사이트 호스팅 기능입니다.

간단한 개인 홈페이지, 프로젝트 소개 페이지, 문서 사이트, 수업 예제 사이트를 공개할 때 유용합니다.

GitHub Pages를 이해하면 GitHub가 단순한 코드 보관함이 아니라, 웹 출판 도구로도 쓰일 수 있다는 점을 알 수 있습니다.
특히 핸드메이드 웹이나 HTML 실습에서는 GitHub Pages가 좋은 출발점이 될 수 있습니다.

10. 라이브러리와 패키지

10.1. 라이브러리

라이브러리는 개발자가 재사용할 수 있도록 미리 만들어둔 코드 묶음입니다.

개발자가 모든 기능을 처음부터 직접 만들면 시간이 많이 걸립니다.
그래서 자주 필요한 기능은 라이브러리로 가져다 씁니다.

예를 들어 날짜 계산, 그래프 그리기, 애니메이션, 이미지 처리, 데이터 요청, UI 컴포넌트 같은 기능은 이미 좋은 라이브러리가 많습니다.

라이브러리를 쓰는 것은 남의 코드를 무작정 복사하는 것이 아닙니다.
검증된 도구를 프로젝트에 맞게 가져와 생산성을 높이는 개발 방식입니다.

10.2. 패키지

패키지는 설치하고 배포할 수 있도록 코드와 관련 정보를 하나로 묶은 단위입니다.

패키지 안에는 보통 코드, 버전 정보, 설명, 의존성 목록, 설정 파일 등이 들어갑니다.
의존성은 어떤 패키지가 작동하기 위해 함께 필요한 다른 패키지를 뜻합니다.

JavaScript에서는 npm 패키지를 많이 사용합니다.
Python에서는 pip나 uv 같은 도구를 통해 패키지를 설치할 수 있습니다.

패키지를 이해할 때 중요한 점은 버전입니다.
같은 패키지라도 버전이 다르면 동작이 달라질 수 있습니다.
그래서 실제 개발 프로젝트에서는 어떤 패키지의 어떤 버전을 쓰는지 기록하고 관리합니다.

11. 로컬 서버와 localhost

11.1. 로컬 서버

로컬 서버는 내 컴퓨터 안에서 실행되는 서버입니다.
인터넷에 공개된 서버가 아니라, 개발자가 작업 중인 컴퓨터에서 테스트하기 위해 실행하는 서버입니다.

웹사이트나 웹앱을 만들 때 매번 인터넷 서버에 올려서 확인하면 비효율적입니다.
그래서 개발 중에는 내 컴퓨터에서 서버를 실행하고, 브라우저로 접속해 결과를 확인합니다.

로컬 서버는 다음 작업에 유용합니다.

  • 웹 페이지가 제대로 렌더링되는지 확인합니다.
  • 버튼과 입력 폼이 작동하는지 테스트합니다.
  • CSS 반응형 레이아웃을 확인합니다.
  • JavaScript 오류를 확인합니다.
  • API 연결 전 임시 데이터로 화면을 개발합니다.
  • 배포 전에 기능을 검증합니다.

11.2. localhost

localhost는 현재 사용 중인 자기 컴퓨터를 가리키는 호스트 이름입니다.
브라우저에서 localhost로 접속하면 외부 서버가 아니라 내 컴퓨터 안에서 실행 중인 서버를 찾습니다.

예를 들어 다음과 같은 주소가 나올 수 있습니다.

%%
http://localhost:3000
http://localhost:5173
http://127.0.0.1:8000
%%

여기서 3000, 5173, 8000 같은 숫자는 포트 번호입니다.
포트는 한 컴퓨터 안에서 여러 서버나 프로그램을 구분하기 위한 번호입니다.

localhost는 외부 사용자가 접속하는 공개 주소가 아닙니다.
다른 사람에게 보여주려면 호스팅, 배포, 공유 터널, 클라우드 서버 같은 별도 방법이 필요합니다.

|| 1 | WWW, World Wide Web | 웹이 인터넷과 같은 말이 아니라는 점을 설명합니다. 인터넷은 네트워크이고, 웹은 그 위에서 브라우저와 서버가 문서와 데이터를 주고받는 정보 시스템입니다. ||
|| 2 | HTML | HTML은 웹 페이지의 구조와 의미를 만드는 언어입니다. 제목, 문단, 링크, 이미지 설명을 정하는 일은 웹에서 글의 구조를 짜는 일입니다. ||
|| 3 | CSS | CSS는 HTML 문서가 어떻게 보일지 정합니다. 색, 글꼴, 여백, 배치, 반응형 레이아웃을 통해 읽기 좋은 화면을 만듭니다. ||
|| 4 | JavaScript | JavaScript는 웹 페이지에 동작을 추가합니다. 버튼 클릭, 데이터 불러오기, 화면 업데이트, 인터랙션을 담당합니다. ||
|| 5 | Handmade Web | HTML을 단순한 기술이 아니라 개인 출판, 글쓰기, 손으로 만드는 웹의 도구로 설명합니다. ||
|| 6 | 호스팅 | 내 컴퓨터에 있는 파일을 다른 사람이 볼 수 있게 하려면 서버에 올려야 합니다. 이것이 호스팅입니다. ||
|| 7 | 클라우드 | 클라우드는 서버, 저장소, 데이터베이스 같은 컴퓨팅 자원을 인터넷으로 빌려 쓰는 방식입니다. ||
|| 8 | 데이터베이스 | 데이터베이스는 웹앱의 기억입니다. 회원, 글, 댓글, 수강 기록, 주문, 권한 같은 정보를 저장하고 관리합니다. ||
|| 9 | GitHub, 패키지, 로컬 서버 | GitHub는 코드와 변경 이력을 관리합니다. 패키지는 필요한 코드를 설치하고 관리하게 해줍니다. 로컬 서버와 localhost는 배포 전에 내 컴퓨터에서 먼저 테스트하게 해줍니다. ||
|#

14. 마무리 설명

웹을 이해한다는 것은 단순히 HTML 태그 몇 개를 외우는 일이 아닙니다.
웹이 어떻게 생겨났고, 브라우저와 서버가 어떻게 대화하며, HTML과 CSS와 JavaScript가 각각 어떤 역할을 하는지 이해하는 일입니다.

그리고 웹은 기술인 동시에 글쓰기의 공간입니다.
HTML은 문서의 구조를 만들고, 링크는 생각과 생각을 연결하고, CSS는 읽는 리듬과 분위기를 만들고, JavaScript는 페이지가 살아 움직이게 합니다.

핸드메이드 웹의 관점은 이 기본기를 다시 소중하게 보게 합니다.
웹은 꼭 거대한 플랫폼이나 복잡한 앱이어야만 하는 것이 아닙니다.
작은 HTML 파일 하나, 개인적인 링크 모음 하나, 수업 노트 하나도 웹의 중요한 형태가 될 수 있습니다.

호스팅, 클라우드, 데이터베이스는 그 작은 페이지가 실제 서비스와 프로젝트로 커질 때 필요한 기반입니다.
처음에는 HTML 파일 하나로 시작해도 좋습니다.
그다음 CSS로 분위기를 만들고, JavaScript로 동작을 붙이고, 호스팅으로 공개하고, 필요하면 데이터베이스와 클라우드로 확장하면 됩니다.

AI 시대에도 이 기본기는 사라지지 않습니다.
AI가 코드를 도와줄 수는 있지만, 어떤 웹을 만들고 싶은지, 어떤 글을 남기고 싶은지, 어떤 구조와 미학을 선택할지는 여전히 사람의 몫입니다.
웹을 배운다는 것은 결국 인터넷 위에 자기만의 방을 만들 수 있는 힘을 배우는 일입니다.
